# Technical writing

Write documentation in clear technical English. Use these ASD-STE100-based rules where practical. We do not require full STE compliance or dictionary checks, because that has a high maintenance cost.

1. Use short sentences. Procedural sentences: 20 words or fewer. Descriptive sentences: 25 words or fewer.
2. Write one instruction per sentence.
3. Use the imperative for instructions: "Run the script." Not "You should run the script."
4. Use the active voice.
5. Use one word for one meaning. Do not use synonyms for the same thing (for example, always "verification script").
6. Put conditions first: "If the build fails, read the log."
7. Use tables and numbered steps for procedures.
8. Do not use idioms, humor, or marketing words.
9. Use code formatting for commands, paths, and identifiers.
10. Write only what the repository actually does. If something is planned, say "planned".

Reference: ASD-STE100, https://www.asd-ste100.org/. The specification is copyrighted. Do not copy it into the repository.
